# Проект ARCHWALK для Rhino 8 25

Версия проекта 1.0 • 17 сентября 2026 • Язык интерфейса русский, английский как дополнительный.

ARCHWALK — рабочее название плагина, который позволяет поставить наблюдателя в архитектурную модель, заранее увидеть его взгляд и затем управлять камерой как в FPS. Этот пакет предназначен для передачи агентам Cursor. Он содержит проект продукта и техническое задание, а не реализацию плагина.

## Что получит пользователь

1. Нажимает **Поставить наблюдателя** и указывает место у ног.
2. Двигает мышь: силуэт, стрелка и сектор обзора показывают направление, маленькое окно показывает будущий кадр.
3. Вторым кликом фиксирует направление. Enter — **Войти**.
4. Ходит на WASD, смотрит мышью, двигается боком на A и D. Высота глаз по умолчанию 1550 мм, скорость 1,3 м/с.
5. Tab освобождает мышь и ставит прогулку на паузу. Esc завершает прогулку, оставляя найденный ракурс. Backspace завершает её с возвратом прежнего вида.

На обычном полу включается следование поверхности. Для незаконченной модели есть движение по фиксированной отметке, для перехода между этажами и наружных обзоров — полёт. Прохождение сквозь стены разрешено в первой версии; физические столкновения не являются условием удобной архитектурной навигации.

## Принятые исходные условия

| Вопрос | Решение проекта |
| --- | --- |
| Основная платформа | Rhino **8.25**, Windows x64, настольный Rhino |
| Почему Windows | Рабочее допущение для первой реализации; ОС пользователь отдельно не указал |
| Среда | C#, RhinoCommon, .NET 8, Eto.Forms; адаптер ввода для Windows |
| Модель | Геометрия в натуральном масштабе; реальные единицы документа |
| Вертикаль | Мировая ось Z; наклонённый CPlane не наклоняет человека |
| Высота | 1550 мм от опорной точки у ног до глаз; меняется в настройках |
| Сохранение | Наблюдатели внутри 3dm; личные настройки отдельно |
| Отображение | Родной viewport Rhino и его геометрия |
| Управление | Свободный взгляд мышью после явного входа, физические позиции WASD при русской и английской раскладке |

Версия для macOS потребует своего адаптера ввода и проверки в Rhino for Mac. Её нельзя объявлять готовой только потому, что ядро написано на C#. Совместимость с Rhino 9, Rhino.Inside, старым .NET Framework и внешними окнами рендереров не входит в первую поставку.

## Что обязательно для первой готовой версии

Установка в два клика с живым превью; плавный FPS-контроль; физический масштаб; три режима движения; безопасный захват и освобождение ввода; повторный вход в сохранённых наблюдателей; восстановление исходного viewport; сохранение в 3dm и Undo/Redo для правок наблюдателя; сохранение найденного кадра в Named Views.

Состояние «камера как-то двигается» не считается завершением. Проверка идёт по документу 05. Следование полу входит в полную версию 1.0, хотя реализуется после базового движения по отметке. Объём v1 нельзя тихо сократить до одного прототипа.

## Как передать пакет Cursor

Распаковать папку целиком в рабочий проект и дать агенту сначала прочитать этот файл, затем документы 01–06. В документе 04 находится готовая инструкция для начала реализации. Ссылки внутри пакета относительные, поэтому сохраняйте имена файлов.

Правило разрешения расхождений: явные последующие указания владельца продукта имеют приоритет; за пользовательское поведение отвечает 01; за числа, клавиши и математику — 02; за интеграцию и данные — 03; за порядок работ — 04; за проверку — 05. Если критерий теста противоречит спецификации, агент фиксирует противоречие и согласует изменение документов, а не выбирает удобное поведение молча.

## Статус технической достоверности

Проверены официальная справка Rhino 8, документация McNeel по RhinoCommon и документация Microsoft по вводу Windows. Работающего Rhino 8.25 в среде подготовки этого проекта не было. Проект не выдаёт документированный API за проверенное поведение конкретной сборки.

Онлайн-справочник RhinoCommon обновляется и уже показывает страницы более новых Rhino. Поэтому первая задача реализации — собрать короткие технические прототипы на установленном **8.25**: ввод без утечки в командную строку, независимое превью, точное восстановление камеры и сохранение данных. Это ограниченные проверки реализации, а не пересмотр пользовательской концепции.
